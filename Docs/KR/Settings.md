# 설정

`UnLua 툴바->설정`을 통해 열거나, `프로젝트 설정-> 플러그인` 인터페이스에서 해당 옵션 탭을 찾을 수 있습니다.

## 1. 런타임 설정

### 시작 모듈 이름

Lua 환경이 시작될 때 지정된 스크립트 모듈을 즉시 실행합니다. 예를 들어 이 옵션이 **Main**으로 구성되면 **Main.lua**를 실행합니다. 비워두면 어떤 스크립트 모듈도 실행하지 않습니다.

### 무한 루프 감지

타임아웃 시간(단위: 초)을 설정하여 Lua 코드가 무한 루프에 빠져 게임이 응답하지 않는 것을 방지합니다. 기본값은 0초(비활성화)입니다.

참고: 감지는 Lua Hook API에 기반하므로 Lua 가상 머신이 바이트코드를 실행할 때의 무한 루프만 방지할 수 있으며, C++ 레이어에서 실행이 발생하면 여전히 정지될 수 있습니다.

### 댕글링 포인터 검사

Lua측에서 구조체와 컨테이너의 참조를 캐시하는 것을 금지하고, C++에서 Lua로의 완전한 호출이 완료된 후 이들을 무효로 표시합니다.

### 충돌 시 Lua 스택을 로그에 출력

충돌이 감지되면 모든 Lua 환경의 스택을 로그에 출력하여 문제 해결을 돕습니다. 기본값은 활성화입니다.

### Lua 환경 할당자

기본 할당자는 모든 `UObject`를 동일한 Lua 환경에 할당하며, 이는 대부분의 응용 시나리오에 적합합니다.

하지만 때로는 환경 분리가 필요할 수 있습니다. 예를 들어 동일한 `GameInstance`의 모든 객체를 같은 환경에 배치하여 게임 종료 시 해당 게임 인스턴스와 관련된 모든 리소스를 한 번에 해제하거나, 일부 Lua 게임 UI 프레임워크가 단일 프로세스 다중 게임 인스턴스용으로 설계되지 않아 단일 프로세스에서 여러 게임 인스턴스를 시작할 때 객체 충돌 문제가 발생하는 경우, `ULuaEnvLocator_ByGameInstance`를 사용하여 상호 분리할 수 있습니다.

`ULuaEnvLocator`를 상속하여 자체 할당 로직을 구현할 수도 있지만, 분리가 샌드박스가 아니라는 점에 주의해야 합니다. 여전히 UE 인터페이스를 통해 다른 환경의 객체에 접근할 수 있습니다.

### Lua 모듈 로케이터

기본적으로 객체를 Lua에 바인딩할 때 생성되는 `GetModuleName`에 바인딩 모듈 경로를 수동으로 입력하거나 `Alt`를 눌러 블루프린트 리소스 경로에 따라 자동으로 채울 수 있습니다.

자체 바인딩 규칙을 구축하려는 경우, 예를 들어 `Content/Blueprints` 디렉토리의 모든 블루프린트를 `Content/Script`의 동일한 이름의 Lua 스크립트에 직접 바인딩하거나 스크립트 이름의 `BP_` 접두사를 제거하는 등의 작업을 할 수 있습니다.

이러한 요구사항에 대해 `ULuaModuleLocator`를 상속하여 자체 자동 바인딩 규칙을 구현할 수 있습니다. 이렇게 하면 어떤 블루프린트가 어떤 스크립트에 바인딩되었는지 확실하지 않은 상황을 피하고 관리가 더 편리해집니다.

### 사전 바인딩 타입 목록

에디터 환경에서 `UBlueprintFunctionLibary`와 `UAnimNotifyState`와 같은 타입은 PIE 종료 후에도 파괴되지 않습니다. PIE에 두 번째로 진입할 때 UnLua는 이들의 생성 이벤트를 포착할 수 없어 Lua 바인딩이 실패할 수 있습니다. 이러한 "상주" 타입을 구성에 추가하면 Lua 환경 시작 후 메모리에 있는 이들의 하위 클래스를 즉시 바인딩합니다.

## 2. 에디터 설정

### 핫 리로드 모드

- 자동: 코드 변경 시 즉시 리로드
- 수동: 단축키 `Alt+L` 또는 툴바의 `핫 리로드` 메뉴 옵션으로 핫 리로드 트리거
- 안 함: 핫 리로드 메커니즘 비활성화

### 지능형 제안 정보 생성

Lua를 위한 지능형 제안 정보를 생성할지 여부, 사용 과정은 [여기](IntelliSense.md)를 참조하세요

### 자동 시작

기본적으로 UnLua 모듈은 게임 시작과 함께 자동으로 활성화되어 바인딩 가능한 모든 객체를 포착합니다. 하지만 때로는 자체 게임 시작 과정이 있을 수 있으므로, 이 옵션을 끄고 적절한 시기에 `UnLua::Startup()`을 통해 시작할 수 있습니다.

*참고: 재시작 컴파일 후 적용*

### UnLua 디버그 코드 활성화

이 옵션을 활성화하면 UnLua와 관련된 더 자세한 디버그 정보를 얻을 수 있습니다. 기본값은 비활성화입니다.

*참고: 재시작 컴파일 후 적용*

### Insights 분석 지원 활성화

이 옵션을 활성화하면 Insights에서 UE가 Lua 오버라이드 함수를 호출하는 분석 지원을 얻을 수 있습니다.

### UFunction 호출 매개변수 지속 캐시 활성화

각 UFunction에 대해 캐시 블록을 생성하고, UE와 Lua 상호 작용 호출 시마다 이 메모리를 재사용하여 반복적인 메모리 할당/해제 오버헤드를 절약합니다. 기본값은 활성화입니다.

*참고: 재시작 컴파일 후 적용*

### 타입 검사 활성화

Lua가 UE를 호출할 때마다 매개변수 타입 검사를 수행합니다. 로컬 개발 시에는 활성화하고 게임 테스트/릴리스 시에는 비활성화하여 더 나은 성능을 얻는 것을 권장합니다. 기본값은 활성화입니다.

*참고: 재시작 컴파일 후 적용*

### RPC 호출 지원 활성화

기본값은 활성화입니다. 비활성화하면 모든 오버라이드된 함수 호출을 로컬 호출로 기본 설정하고 Out 매개변수에 대해 캐시를 예약하여 이러한 함수 호출의 약간의 성능 향상을 얻습니다. 게임에서 온라인 기능을 사용하는 경우 이 옵션을 비활성화하지 않는 것을 권장합니다.

*더 이상 사용되지 않음: 이 옵션은 향후 버전에서 제거될 예정입니다.*

*참고: 재시작 컴파일 후 적용*

### 오버라이드된 함수 호출 지원 활성화

기본값은 활성화입니다. Lua에서 `self.Overridden`을 사용하여 오버라이드된 원본 함수에 접근할 수 있게 합니다.

*참고: 재시작 컴파일 후 적용*

### FText 지원 활성화

기본값은 비활성화입니다. 기본적으로 `FText` 타입은 `lua string` 방식으로 전달되어 일부 다국어 정보가 손실됩니다. 이 옵션을 활성화하면 `FText`가 C++ 객체 방식으로 전달되어 더 나은 다국어 지원을 얻을 수 있습니다.

*참고: 재시작 컴파일 후 적용*

### C++로 Lua 환경 컴파일 사용

기본값은 비활성화입니다. 활성화하면 더 정확한 크로스 언어 상호 작용 예외 처리 지원을 얻을 수 있지만, C로 컴파일된 서드파티 라이브러리 소스 코드의 Lua 심볼 문제를 수동으로 처리해야 합니다.

*참고: 재시작 컴파일 후 적용*

### 사용자 정의 Lua 버전

기본값은 `lua-5.4.3`이며, `lua-5.4.4` 또는 기타 사용자 정의 버전으로 수정할 수 있습니다. 프로젝트 컴파일 시 `Plugins/UnLua/Source/ThirdParty/Lua`의 해당 이름 디렉토리 소스 코드를 사용합니다.

*참고: 재시작 컴파일 후 적용*

### UE4 네임스페이스

구버전에서 `UE4`를 통해 접근해야 하는 코드와의 호환성(새 버전에서는 `UE`).

*참고: 재시작 컴파일 후 적용*

### 반환값 순서

구버전에서 Out 매개변수를 반환값 앞에 배치해야 하는 코드와의 호환성.

*참고: 재시작 컴파일 후 적용*

### 블루프린트 리소스 경로 접미사

구버전에서 블루프린트 리소스 로드 시 경로 끝에 자동으로 `_C`를 추가해야 하는 코드와의 호환성.

*참고: 재시작 컴파일 후 적용*

### UTF-8 BOM 파일 헤더 호환성

기본값은 비활성화입니다. 구버전에서는 BOM 파일 헤더가 있는 Lua 파일과 호환되었지만, 런타임 Lua 로딩에 불필요한 감지 오버헤드가 발생했습니다. 자동화 도구를 사용하여 Lua 파일 인코딩이 정확한지 확인하는 것을 권장합니다.

이 옵션을 비활성화하면 에디터에서는 호환성을 유지하지만 해당 경고 로그가 표시됩니다.

*참고: 재시작 컴파일 후 적용*

### 매개변수 전달 방식

구버전에서 UE가 Lua로 오버라이드된 `UFunction`을 호출할 때 객체 매개변수(예: 컨테이너, 구조체)를 포인터로 전달했습니다. Lua에서 직접 수정하려면 수동 복사 작업(예: ToTable 또는 Copy)을 수행해야 했습니다. 이는 대부분의 읽기 전용 상황에서 잘 작동하고 좋은 성능 이익을 제공하지만 추가적인 정신적 부담도 가져왔습니다. 이 옵션을 비활성화하면 이 동작을 기본 자동 복사로 조정할 수 있습니다.

### 새 버전 확인

새 버전이 발견되면 콘솔에 새 버전 정보를 출력합니다.
